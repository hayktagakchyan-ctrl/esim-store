Актуально на момент последнего разговора с владельцем проекта. Проверяй
живьём (Railway → Variables, Name.am → DNS Records) перед тем как полагаться

## Три сервиса Railway

| Сервис | Что | Домен |
|---|---|---|
| **webapp** | Сайт + Mini App + чат поддержки | `www.kaline.am` (custom domain, CNAME → `*.up.railway.app`) + собственный `*.up.railway.app` (используется как `MINIAPP_URL` для кнопки бота — НЕ меняй на kaline.am, см. ниже) |
| **bots** | Оба Telegram-бота, polling | нет домена, не нужен |
| **Admin** | Админ-панель | свой `*.up.railway.app`, без кастомного домена |

**Почему `MINIAPP_URL` должен остаться на `*.up.railway.app`, а не на
`www.kaline.am`**: в `webapp/app.py` есть мидлвар
`redirect_bot_paths_on_public_domain` — на публичном домене (`kaline.am`/
`www.kaline.am`) он редиректит вообще ЛЮБОЙ путь, кроме `/shop/*` и ещё
нескольких, на `/shop/`. Это специально, чтобы кто-то, зашедший на сайт из
браузера, не видел сырой интерфейс бота. Но если `MINIAPP_URL` (кнопка,
которую Telegram открывает) будет указывать на `www.kaline.am`, бот тоже
попадёт под этот редирект и перестанет открываться.

## DNS (Name.am, DNS работает через Amazon Route 53)

Уже настроено на `kaline.am`:
- `_dmarc` (TXT) — DMARC-политика
- `resend._domainkey` (TXT) — DKIM для Resend (почта)
- `rsend` / `send` (CNAME) — SPF-записи Resend
- `www` (CNAME → `*.up.railway.app`) — сам сайт
- `_railway-verify.www` (TXT) — подтверждение владения для Railway

**НЕ настроено / известная проблема**: голый `kaline.am` (без www) не
открывает сайт. DNS-стандарт не разрешает CNAME на корневом домене — обычно
это решается через ALIAS-запись (Route 53 такое умеет нативно) или через
"Domain Forwarding" у регистратора. У панели Name.am в выпадающем списке типов
записи ALIAS не оказалось (только A/AAAA/CNAME/MX/SRV/SPF/TXT/PTR) — то есть
через саму DNS-панель эта проблема не решается. Два реальных варианта,
которые ещё не пробовали до конца:
1. Написать в поддержку Name.am напрямую — спросить именно про "Domain
   Forwarding" (не DNS Records) для этого домена; такая функция была на
   скриншотах у пользователя раньше, но найти её снова в интерфейсе не
   получилось.
2. Перевести DNS на Cloudflare (бесплатно поддерживает CNAME flattening на
   корневом домене без всяких ALIAS-плясок) — сменить NS-серверы в Name.am,
   перенести туда все 5 записей выше заново. Более надёжно, но требует
   ~20-30 минут работы и временного даунтайма почты/сайта на время
   распространения NS.

## Email (Resend)

Домен `kaline.am` подтверждён в Resend (Verified, все DNS-записи выше — под
это). `SMTP_FROM_EMAIL` должен быть на домене `kaline.am` (например
`noreply@kaline.am`) — Resend не даст слать с чужого домена. `RESEND_API_KEY`
нужно вписать в сервис **webapp** (там же, где раньше был SMTP — теперь
письма идут через HTTP API Resend, не SMTP, см. `docs/DECISIONS.md`).

Один раз ключ Resend был случайно вставлен прямо в переписку — тогда его
пересоздавали заново. Если это повторится с любым секретом — считать
скомпрометированным и перевыпускать, не полагаться на "но его же не
использовали успеть".

## Переменные окружения — чек-лист перед реальным запуском

Смотри `app/config.py` — там у каждой переменной подробный комментарий, что
она делает. Коротко, что проверить в Railway → сервис **webapp** → Variables
перед тем как пускать реальных клиентов:

- [ ] `ENABLE_TEST_PAYMENT` = `false` — **критично**, иначе любой клиент
      получает eSIM бесплатно через кнопку тестовой оплаты
- [ ] `IDRAM_REC_ACCOUNT` / `IDRAM_SECRET_KEY` — заполнены реальными
      значениями, если Idram — рабочий способ оплаты
- [ ] `RESEND_API_KEY` — вписан (иначе письма не уходят, только дублируются
      в бот поддержки)
- [ ] `SMTP_FROM_EMAIL` — на домене `kaline.am`, не на постороннем
- [ ] `PUBLIC_BASE_URL` — `https://www.kaline.am` (уже переключено)
- [ ] `MINIAPP_URL` — **должен остаться** на `*.up.railway.app` (см. выше)
- [ ] `SECURE_COOKIES` = `true` (уже так — отключает Swagger/ReDoc в проде)
- [ ] Секреты, которые когда-либо попадали в переписку/скриншоты
      (`ADMIN_PANEL_PASSWORD`, `ADMIN_PANEL_SECRET_KEY`,
      `SHOP_SESSION_SECRET_KEY`, токены ботов) — перевыпущены после того как
      "засветились"

Одни и те же переменные (`PUBLIC_BASE_URL`, `DATABASE_URL` и т.п.) должны
совпадать между сервисами **webapp** и **bots** и **Admin** там, где логика
это предполагает — Railway не синхронизирует Variables между сервисами
автоматически, обновлять нужно в каждом отдельно.
